# Code map audit

The dashboard labels every mapped code function in all three Box revisions by
address range. The boundaries are existing symbols, not guessed translation
units. The large prefix before the SDK is labeled **Application / middleware**:
its internal functions remain mostly unnamed, so narrower ownership is not
claimed.

| Region | GPXE01 start | GPXP01 start | GPXJ01 start | Evidence |
| --- | --- | --- | --- | --- |
| Startup / CRT | `80003100` | `80003100` | `80003100` | `.init`, `__start`, register/data init and memory helpers |
| Application / middleware | `800056C0` | `800056C0` | `800056C0` | `.text` prefix before the SDK entry |
| Dolphin SDK | `801279EC` | `80128E48` | `80124B00` | `PPCMfmsr`, followed by OS, EXI, SI, DVD, CARD and GX symbols |
| CodeWarrior runtime | `8015A888` | `8015BD14` | `801572C8` | `__va_arg`, followed by exception, stdio and math routines |
| MetroTRK / debug I/O | `80164854` | `80165CE0` | `80161090` | `TRKNubMainLoop`, followed by TRK and debug transport symbols |

The US report maps 1,467,176 code bytes and all 6,346 function symbols; 395
have non-placeholder names. PAL maps 1,472,436 code bytes and all 6,353
functions (395 named). JP maps 1,451,640 code bytes and all 6,313 functions
(392 named). US has seven linked, byte-exact C functions (52 bytes); PAL and
JP still have generated splits rather than linked C progress reports.

For display, an autogenerated build unit crossing a boundary becomes two map
regions, while its original build unit remains unchanged. Function sizes, not
section spans, determine code-byte totals: `.init` spans 9,284 bytes but has
only 1,296 bytes of functions, and the US debugger span contains 12 bytes of
padding. The source map and DOL checks remain the authority for linked matches.
