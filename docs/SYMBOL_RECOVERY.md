# Symbol recovery

The three baseline DOLs relink byte-exactly, but their autogenerated symbol
maps initially named only 305, 305, and 302 of 6,346, 6,353, and 6,313
functions respectively. The disc filesystem contains no `.map`, `.sym`, or
debug ELF. Its archived assets and DOL strings do preserve some original
resource and source-file names, but they do not provide a full function map.

`harness/box_symbol_candidates.py` compares complete function instruction
sequences with the local XD and Colosseum builds. It masks PowerPC branch
displacements, requires at least eight instructions, and rejects signatures
that occur more than once in any compared build. The ignored per-region
`build/decomp-support/<version>/symbol-candidates.json` reports preserve the
candidate addresses and reference units. A matching shape is only a naming
lead: local wrappers and game functions can still collide semantically.

`harness/box_promote_symbols.py` promoted only the 90 names whose unique
signatures agreed in XD and Colosseum **and** appeared in all three Box
regions. These are shared SDK/runtime functions, not inferred Box game names.
Their per-region addresses and reference evidence are in
`research/symbols/shared-sdk.json`. The script validates every prior name,
address, and size before rewriting `config/<version>/symbols.txt`.

After the rename, named-function counts are 395/6,346 (GPXE01), 395/6,353
(GPXP01), and 392/6,313 (GPXJ01). All three configured relinks passed their
original DOL SHA-1 checks. These names do not establish translation-unit
boundaries or linked C matches. Additional single-reference candidates remain
unapplied pending call-site, vtable, or other independent evidence.

## Where the reference names come from

XD's strongest game-code names originate in the `NXXJ01` demo linker map.
The XD project ports those names to the `GXXE01` retail binary only when the
binary correspondence is supported; its contribution rules explicitly prefer
demo-map names and reject speculative names. Its SDK names also come from
recognized Dolphin SDK and runtime implementations.

Colosseum does not rely on one universal naming file. Its evidence records cite
the XD demo map, TeamOrre's XD symbol map, trevor403's XD disassembly, known
SDK sources, strings, and exact or structural cross-title matches. It preserves
address names where those sources do not justify a semantic name.

Box follows the same evidence order: canonical SDK/runtime sources first,
agreement between independently mapped Colosseum and XD functions second, then
strings and call-site behavior as review leads. A nearby named anchor may label
a dashboard region, but it does not rename every function in that region or
prove an original translation-unit boundary.
