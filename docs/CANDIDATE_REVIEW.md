## Whole-DOL leaf promotion

The whole-DOL conservative template sweep found 578 instruction-exact leaves
covering 3,868 bytes. Promotion requires GC/1.2.5n, a 100% function score, an
empty instruction diff, a matching saved source hash, and a target object with
no non-text ownership. This last check excludes `fn_8002E860`, whose original
object also owns a four-byte `.ctors` entry. The remaining 577 functions and
3,864 bytes now link as 264 grouped C units. The generated report marks every
one of those units 100%, and the full DOL matches the retail SHA-1.

Across GPXE01, 711 functions and 13,776 code bytes are now source-backed. The
grouping is mechanical evidence from contiguous function ranges, not a claim
about original translation-unit ownership.

The 728-byte `SetInterruptMask` has byte-identical linked implementations in
the reference projects, but its standalone split is only 71.83%. The full SDK
translation unit changes its branch and condition-code shape, so it remains
assembly-backed until that source context is reproduced without importing
unowned functions or data.

`fn_800BCC84` lies in the largest autogenerated unit and is still **not**
exact: GC/1.3.2 scores 99.09%. Box loads the vtable pointer through `r12`,
while the candidate uses `r4` before loading the call target into `r12`.
Several equivalent C pointer and struct expressions preserve that difference;
changing syntax alone has not established the original compiler setup.

The original m2c draft for `fn_80091928` also lies in that unit. Its objdiff
fuzzy score is 100%, but the instruction comparison differs at a floating
constant relocation (`lbl_8022C6F8@sda21` versus a compiler-local constant).
It remains a draft, not a saved exact candidate.

The project-wide 257-512-byte m2c pass selected 96 functions and generated 86
drafts. Five compiled: `fn_8007DB5C` (99.09%), `fn_801129C8` (88.09%),
`fn_8013A71C` (88.02%), `fn_80097EA8` (83.92%), and `bitrev` (79.02%). None of
the five m2c drafts is instruction-exact. The matched corpus implementation of
`bitrev` was separately scratch-verified at 100% and promoted after the full
DOL checksum passed.

## Largest unit

The original `auto_03_8008AB74_text` range spans 219,776 code bytes and 406
functions. Mechanical function splits now link 90 functions (3,180 bytes,
1.45%) as C across 66 complete subunits; 316 functions and 216,596 bytes remain
assembly-backed. The full DOL relink matches the retail SHA-1. These splits
prove byte-exact replacement at the stated addresses, not the original source
file boundaries or compiler provenance.

The first RPC-free leaf sweep found 31 instruction-exact scratch hypotheses
(224 bytes), subsequently promoted with other exact drafts. A bounded m2c
sweep of 85 remaining functions up to 64 bytes produced 20 instruction-exact
drafts, all now linked. Two more functions (`fn_800917B4` and
`fn_800BD72C`) were fixed by correcting inferred argument positions and
linked after a full SHA-1 check. The current input-checked leaf sweep has no
further template matches. Artifacts remain under ignored
`build/decomp-support/GPXE01/leaf-sweeps/8008AB74-800C05F4/` and
`build/decomp-support/GPXE01/validation/`.

The next 65-128-byte sweep drafted 90 of 91 functions. Of 11 scorer-100%
results, nine had no instruction diff and were linked; two had floating
constant relocation differences. Correcting missing downstream call arguments
also linked `fn_800B9A80` and `fn_800BCF40`, and a named accumulator fixed
`fn_800BFB1C`. The 129-256-byte sweep drafted 65 of 68 functions but yielded
no instruction-exact result: its two scorer-100% results also differ at a
floating constant relocation. These scorer results are not linked progress.

Further type review linked seven more functions. A volatile status word explains
the required reloads in `fn_80096808`; a retained local preserves the branch
shape in `fn_800BBE30`. Volatile float source loads reproduce four contiguous
copy functions at `0x8008F0B8..0x8008F14C`, and a wider temporary fixes
`fn_8008DF7C`. All seven passed the full DOL SHA-1 check. The adjacent
`fn_8008DFD4` draft still differs in register allocation and remains assembly.

The contiguous `0x8008AB74..0x8008AD10` stretch is now C-backed across six
functions (412 bytes). Typed pointer fields recovered the lookup and two array
append functions that raw m2c could not compile; concrete external call and
stack-local types recovered the two preceding functions. Typed calls, pointer
adjustments, and a predecrementing struct access linked six more functions;
four adjacent call wrappers then linked with exact instruction and DOL checks.
Explicitly retaining a product before loading its intercept made
`fn_800916C4` and `fn_8009173C` instruction-exact. Both now share a linked C
unit, with a full SHA-1 check. The latest complete range sweep
(`e92927256eb310332c38`) has 285 saved drafts and 31 unsupported functions.
Scratch validation compiles 33 of those drafts, but none is instruction-exact:
four scorer-100% results retain floating-constant relocation differences, 29
are non-exact, and 252 fail standalone compilation.
